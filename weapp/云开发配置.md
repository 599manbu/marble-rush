# 实时对战 · 云开发配置

实时对战依赖微信云开发。按下面步骤配置一次即可，之后代码不用再改。

## 1. 填环境 ID

打开 `game.js`，找到：

```js
const CLOUD_ENV = '';   // 填云开发环境 ID；留空则用默认环境
```

把云开发控制台「设置 → 环境 ID」里的值填进去，例如：

```js
const CLOUD_ENV = 'manbu-d5g2qu3sb1xxxxxx';
```

如果你只创建了一个云开发环境，留空也能用默认环境；建议还是显式填写，避免多环境时连错。

## 1.1 部署内容安全云函数（提审必需）

审核要求：用户自定义昵称必须经过内容安全检测。项目已内置云函数 `cloudfunctions/msgSecCheck`。

1. 开发者工具左侧应能看到 `cloudfunctions/msgSecCheck`
2. 右键该目录 → **「上传并部署：云端安装依赖」**
3. 等待部署成功（云函数列表出现 `msgSecCheck`）
4. 之后玩家修改昵称时，会先调用 `msgSecCheck`，检测不通过会提示“名称包含违规内容”并拒绝保存

如果没有部署，改名会提示“名称校验服务不可用”，默认的四字名字仍可正常使用。

### 改名提示“校验服务异常(错误码)”

说明云函数已调用，但 `msgSecCheck` 接口返回了错误。处理：

1. 云开发控制台 → 云函数 → `msgSecCheck` → **日志**，查看最近一次调用的错误信息
2. 常见错误：
   - `-604101` / `no permission`：云函数与小程序不是同一个 AppID，或云调用权限未开通
   - `40003` / `invalid openid`：开发者工具模拟器登录态不完整，**用真机测试**
   - `45009`：接口调用频率超限，稍后再试
3. 云函数已内置 v2 失败自动降级 v1 的逻辑；如果 v1 也失败，会返回具体错误码

## 2. 创建数据库集合

云开发控制台 → 数据库 → 新建集合，创建两个：

| 集合名 | 用途 |
|---|---|
| `mr_rooms` | 房间信息：房号、赛道种子、难度、状态 |
| `mr_states` | 玩家实时状态：位置、是否完赛、用时 |
| `mr_ranks` | 全服排行榜：玩家名、已通关数、最快用时 |

### 权限设置（关键）

三个集合都设为：

> **所有用户可读，仅创建者可读写**

（`mr_ranks` 需要“可读”才能拉取全服榜单；每人只写自己那一份成绩）

原因：
- 房主创建房间文档，好友需要读它 → 必须可读
- 每位玩家只写自己的状态文档 → 仅创建者可写
- 如果设成「仅创建者可读写」，好友读不到房间，实时对战会失败

### 建议索引

- `mr_rooms.code`（好友通过房号查询）
- `mr_states.roomId`（按房间监听状态）

## 3. 使用流程

1. 主菜单 → 邀请 → 顶部切到「实时对战」
2. 点「创建房间并邀请好友」→ 自动生成房号并拉起分享
3. 最多 4 名好友点卡片加入，自动进入等待
4. 房主可实时调整 **AI 小球数量（0-5）**；每位玩家点自己的名字可改名（只能改自己）
5. 至少 2 人后房主点「开始对战」→ 所有玩家同时进入倒计时
6. 同一条赛道实时竞速，结算比较用时

## 3.1 房间规则

- 人数上限 **4 人**（含房主）
- AI 数量由房主设置，所有人共享
- 每位玩家只能修改自己的名字，他人的名字只读
- 房主可「换一条新赛道（重新建房）」，会生成新的房号和赛道

## 4. 每日次数

- 每人每天最多 **5 局**实时对战
- 计数存在本机（`localStorage` 的 `mrRT_日期`）
- 卸载重装/清缓存会重置；如果需要严格限制，可以改成云数据库计数

## 5. 费用提醒

实时对战时双方每 100ms 写一次状态：

- 一局 60 秒 ≈ 600 次写入/人
- 加上监听推送的读次数，一局会消耗不少资源点
- 基础套餐 40000 点/月，大约只够几十到一两百局，需按实际使用观察

建议：
- 保留「幽灵对战」作为默认方式（零成本）
- 实时对战保持每日 5 局上限
- 上线后看云开发用量再决定是否升级套餐

## 6. 测试建议

1. 开发者工具编译后，用两台手机（或一台手机 + 开发者工具真机调试）分别进入同一房间
2. 检查双方是否都能看到对方蓝色的实时球
3. 检查结算用时是否正确
4. 检查每日次数是否正确扣减
5. 弱网/断线时观察是否卡住（当前版本没有断线重连，后续可加）

## 7. 已知限制

- 实时位置是 10Hz 同步 + 插值，网络差时对方球会有轻微延迟
- 双方物理各自计算，球与球的碰撞不跨端同步
- 没有断线重连与房间超时清理，退出后房间文档会残留（可在控制台手动清理）
